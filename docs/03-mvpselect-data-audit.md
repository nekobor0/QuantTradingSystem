# MvpSelect 数据审计

审计时间：2026-07-28。来源为 `../MvpSelect/data`，全程只读。机器可读结果位于 `artifacts/mvpselect_audit.json`，可用 `tools/audit_mvpselect.py` 重跑。

## 1. 结论先行

`MvpSelect` 有可复用的 A 股研究资产，但不能直接作为新系统的生产数据层。应通过“登记—映射—质量分级—迁移”的适配流程使用，不能直接复制目录或让策略依赖旧路径。

主要原因：

- 现有 `INVENTORY.md` 显示约 4.4 万行统一数据，但实物已有 2,916 个文件、约 37.28GB、Parquet 元数据合计约 3.25 亿行，清单严重漂移。
- Parquet 有 79 种 schema；扩展日线自身就有 4 种 schema，证券标识同时使用 `code` 和 `symbol`。
- `stock_basic.parquet` 只有 84 只证券，不是全市场 point-in-time 主数据。
- `archive/daily_raw.parquet` 只有 73 只证券、2017-01-03 至 2026-05-28；不能代表全 A 历史行情。
- 扩展日线出现 8,328 个唯一原始标识，但因 `code`/`symbol` 及代码格式混用，这不等于 8,328 只证券；标准化前无法判断真实证券数量，也没有港股通、ETF 全量覆盖证明。
- 合并财务数据 19 个行业文件出现 12 种 schema，列数从 35 到 57，不满足统一数据字典要求。
- 现有系统最终回测实现是向量化引擎；不能证明满足事件驱动、point-in-time、涨跌停/停牌/退市和真实成交时序。

## 3. 扩展日线的 schema 分裂

| 文件数 | 行数 | 标识字段 | 主要列形态 |
|---:|---:|---|---|
| 17 | 9,466,614 | `symbol` | 含 source 与后复权 OHLC |
| 39 | 6,051,133 | `code` | 9 列基础 OHLCV + adj_factor |
| 9 | 1,247,848 | `code` | 另含 adjustflag |
| 2 | 426,117 | `symbol` | 后复权 OHLC 与 source，列顺序不同 |

这也解释了为什么直接把目录当一个 PyArrow dataset 会产生大量伪空值：不同文件的标识列并不一致。审计工具已按 schema 分组后再统一标识，避免把 schema 漂移误判为源数据缺失。

## 4. 可复用性分级

| 资产 | 分级 | 处理方式 |
|---|---|---|
| 扩展日线原始 OHLCV 与 adj_factor | B：可迁移候选 | 统一证券 ID、来源、单位和复权语义；做逐证券交易日覆盖与重复键检查 |
| archive/daily_raw | C：局部样本 | 仅作交叉验证，不作为主行情 |
| stock_basic | C：局部样本 | 不迁移为 instrument master；重建全市场历史主数据 |
| 合并财务统一文件 | C：需重构 | 回到源表，按公告时间和字段字典重新建模 |
| 因子/策略结果 | C：研究证据 | 保存实验档案，不导入生产事实表 |
| 现有因子和策略代码 | B/C：逐项复核 | 检查前视、横截面样本、复权和异常捕获后再移植 |
| 向量化回测代码 | C：快速筛选器 | 可保留作研究基线，不作为正式回测结论 |

## 5. 迁移门禁

每个旧数据集只有满足以下条件才能进入新系统的 curated 层：

1. 登记来源、许可、抓取时间、数据集负责人和哈希。
2. 建立旧标识到 canonical `instrument_id` 的时点映射。
3. 统一日期、时区、币种、价格/成交量单位和复权因子定义。
4. 校验 `(instrument_id, trading_date, frequency, source)` 唯一性。
5. 按证券生命周期和交易日历计算缺口，区分停牌、未上市、退市和源缺失。
6. 通过 OHLC、成交量、涨跌幅、复权连续性与跨源抽样检查。
7. 对财务数据证明 `available_at` 不早于公告可见时间，并保存修订版本。
8. 形成可重复的迁移清单和拒绝清单，不直接覆盖旧资产。

## 6. 本次审计限制

- 没有联网核对当前证券数量、港股通名单或数据源官方口径。
- 尚未做 1,719 万行的全局重复键检查和逐证券交易日缺口矩阵。
- 尚未验证复权因子能否准确重建后复权 OHLC，也未抽查拆分、分红等公司行动。
- Parquet 元数据总行数含重复实验输出，不能理解为独立市场观测数。

这些检查应成为第 1 阶段数据迁移的自动化质量套件，而不是用人工文档补齐。
