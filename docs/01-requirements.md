# 需求与系统边界（基线 v0.1）

## 1. 目标

建立一个可审计、可复现的单账户半自动量化系统。系统每天完成数据更新、质量检查、策略计算、组合建议、风控检查和监控；用户在券商端手工下单，并在系统中回填订单与成交，系统据此重建实际持仓和绩效。

系统优化目标不是“回测收益最大”，而是在可交易约束下稳定生成可解释、可复核的决策。

## 2. 范围内

| 维度 | 边界 |
|---|---|
| 市场 | 沪深主板、创业板、科创板、北交所；每日有效港股通名单内证券；境内交易所上市行业 ETF 和海外资产相关 ETF |
| 方向 | 纯多头；目标现金权重允许为 100% |
| 频率 | 数据可含分钟线；策略与组合最高日频；部分 ETF 可周频 |
| 账户 | 单一实际账户，基准币种 CNY，保留 HKD 现金和汇率暴露 |
| 执行 | 系统生成订单建议，人工审批和券商端下单，人工回填订单/成交/费用 |
| 系统能力 | 数据、因子、策略、组合构建、信号、事件驱动回测、执行台账、风控、监控、报告 |

## 3. 明确不做

- 不自动连接券商下单，不承担 OMS/柜台职责。
- 不做卖空、融资融券、期货、期权、场外基金和非港股通港股。
- 不以 Tick/高频交易为第一阶段目标。
- 不做多账户、多用户权限体系、移动端或高可用集群。
- 不把 Notebook 直接作为生产策略运行器。
- 不保证免费数据源满足商业使用许可、稳定性或完整历史成分股要求。

## 4. 决策时序

默认规则为“收盘后生成，下一可交易时段执行”：

1. 交易日 T 收盘数据完成且质量门禁通过。
2. 只使用在 T 时点已公开、已可获得的数据生成信号。
3. 产生带有效期的目标权重和订单建议。
4. 用户在 T+1 或建议指定窗口手工执行。
5. 成交回填后，系统以实际成交而非建议成交更新账户。

任何声称使用 T 日收盘价成交的回测都必须显式证明该信号在收盘前可得，否则按前视偏差处理。

## 5. 核心业务流程

```mermaid
flowchart LR
    A["数据采集"] --> B["标准化与质量门禁"]
    B --> C["因子与策略计算"]
    C --> D["目标组合与风险预检"]
    D --> E["订单建议"]
    E --> F["人工审批与券商执行"]
    F --> G["订单/成交回填"]
    G --> H["实际持仓、风险与绩效"]
    H --> D
```

## 6. 功能需求

### 数据层

- 统一证券主数据、交易所代码、币种、板块、上市/退市日期和交易单位。
- 保存每日 point-in-time 的港股通资格、指数/行业/ETF 成分和证券状态。
- 保存未复权 OHLCV、复权因子和公司行动；按需生成前/后复权序列。
- 财务数据同时保存报告期、公告时间、实际可用时间、来源和修订版本。
- 每日增量任务具有幂等性、血缘、批次号、重试和质量门禁。
- 质量门禁覆盖唯一键、完整性、合理性、跨源差异、时效性和交易日覆盖。

### 策略与研究

- Notebook 用于探索；进入系统的因子/策略必须是有版本的 Python 模块和配置。
- 策略输出标准化 `target_portfolio`，不得直接修改账户。
- 同一策略代码必须能在回测、论文交易和每日信号中复用。
- 实验记录固定数据快照、代码版本、参数、训练/验证/测试窗口和结果。

### 回测

- 事件循环至少包含 MarketData、Signal、Order、Fill、CorporateAction 事件。
- 支持市价/限价语义、延迟、滑点、佣金、最低佣金、印花税和市场差异。
- 处理停牌、涨跌停、无成交、整手、A 股 T+1、退市和现金分红。
- 输出收益、波动、夏普、Sortino、最大回撤、Calmar、换手、胜率、盈亏比、容量和成本敏感性。
- 必须支持 walk-forward、严格样本外、参数扰动、基准和论文交易。

### 决策信号

- 每个信号含策略/模型/数据版本、生成时间、适用交易日、目标权重、原因码和失效时间。
- 订单建议必须经过账户现金、持仓、交易单位、资格、流动性和集中度预检。
- 用户可接受、部分接受或拒绝建议，并记录原因。

### 执行台账与前端

- 录入订单、部分成交、多次成交、撤单、费用、税费和备注。
- 支持 CSV 导入作为手工逐笔录入的替代方案，但导入后仍需校验确认。
- 显示“建议—订单—成交—持仓”的差异和未对账项。
- 每日收盘对账，差异未解决时阻断次日正式信号发布。

### 风控监控

- 事前：现金、单标的、行业、市场、ETF 类型、流动性、停牌/涨跌停、港股通资格。
- 事中（人工执行期）：建议过期、价格偏离、部分成交和未执行告警。
- 事后：实际暴露、回撤、换手、成本、数据任务、信号任务和对账状态。
- 风控规则分 hard block、approval required、warning，规则和阈值均需版本化。

## 7. 非功能与验收要求

- 可复现：任一信号可追溯到代码、参数、数据批次和输入记录。
- 幂等：同一批次重跑不产生重复事实记录。
- 时点正确：财务和成分数据按当时可知信息查询。
- 可解释：信号至少给出主要因子贡献、过滤原因和风险规则结果。
- 安全：密钥仅从环境或密钥服务读取；日志不记录 token。
- 时间：交易所时间按 `Asia/Shanghai` / `Asia/Hong_Kong` 保存语义，数据库时间戳统一为 UTC。
- 恢复：数据库每日备份；原始数据不可覆盖；生产写操作有审计日志。

## 8. 待用户在实施前确认的参数

- 券商、实际佣金/最低佣金、港股平台费及账户币种结算方式。
- 目标初始资金、最大持仓数、单标的/行业/市场上限和最低成交额。
- 信号执行窗口（次日开盘、VWAP 代理、指定限价等）。
- 可付费数据预算与 Tushare 等服务权限；这决定历史成分和财务 point-in-time 的可得性。
- 首个策略是“个股多因子”“ETF 轮动/择时”还是两者之一；第一阶段应只选一条闭环。
