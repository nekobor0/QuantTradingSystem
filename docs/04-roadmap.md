# 实施路线图与验收

原则：每个阶段形成一个可验证闭环；在数据时点正确和执行模型可靠之前，不扩充策略数量。

## Phase 0：需求与架构冻结（本目录已完成）

交付：范围、时序、模块边界、存储/消息选型、旧数据审计、初版数据字典和后续门禁。

完成标准：用户确认待定参数，并选择第一条策略闭环。

## Phase 1：数据底座

建议先只做 A 股 + 境内 ETF 日线，港股通在基础模型稳定后接入。

工作：

1. 建 PostgreSQL/TimescaleDB schema、迁移工具和数据集登记表。
2. 建证券主数据、交易日历、未复权日线、复权因子、公司行动、成分历史。
3. 接一个主数据源和一个抽样校验源；导入合格的 MvpSelect 日线候选。
4. 实现每日幂等增量、批次血缘和质量门禁。

验收：

- 指定交易日可还原当时可交易证券池。
- 重跑同一批次行数与哈希不变。
- 随机 100 只证券的日期覆盖、OHLC、复权与跨源检查形成报告。
- 任何 hard-fail 数据批次不会发布为可用快照。

## Phase 2：账户、信号和人工执行闭环

工作：当前持仓/现金、目标组合、订单建议、审批、成交回填、费用和对账；完成 Streamlit 驾驶舱。

验收：

- 从一组目标权重生成符合整手、现金和限额的建议订单。
- 支持部分成交和多笔成交；实际持仓只由成交派生。
- 导入券商日结单后可解释所有差异，未对账状态会阻断正式发布。

## Phase 3：事件驱动回测

工作：事件循环、订单状态机、撮合、市场规则、成本、账户和绩效；用固定小样本写黄金测试。

验收：

- 信号不能在生成前成交。
- 停牌、涨跌停、整手、现金不足、最低佣金、印花税和 A 股 T+1 均有测试。
- 同一策略在回测与每日运行使用相同核心函数。
- 与手算案例逐笔一致，并与简单买入持有基准对照。

## Phase 4：首个策略闭环

只选择一个：ETF 择时/轮动通常更适合作为首个闭环，因为证券池小、公司行动和财务时点复杂度较低；个股多因子作为下一阶段。

验收：

- 明确经济假设、适用市场状态和失效条件。
- train/validation/test 严格隔离；完成 walk-forward 和参数敏感性。
- 成本翻倍、成交延迟和信号扰动下仍有可接受表现。
- 通过至少一个预先约定周期的论文交易，期间参数冻结。

## Phase 5：扩市场与运营加固

依次加入个股多因子、港股通、海外相关 ETF、分钟数据。只有出现实测问题才引入 Redis、RabbitMQ 或 ClickHouse。

验收：市场规则表、费用模型、币种/汇率、交易日历、数据许可和对账均有独立测试；监控覆盖数据陈旧、任务失败、信号未执行和风险阈值。

## 不应并行推进的事项

- 在事件驱动引擎未完成前大量调参。
- 在 instrument master 未完成前宣称消除幸存者偏差。
- 同时接入多个免费源但没有来源优先级和冲突规则。
- 在单机日频没有瓶颈证据时部署 Kafka、Redis、ClickHouse 集群。
